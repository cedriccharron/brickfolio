# Brickfolio — contexte pour Claude

Suivi d'investissement LEGO : achats, valeur BrickLink relevée chaque semaine, plus-values. Propriétaire : Cédric. Réponses et textes de l'app en français.

## Architecture (même que Cap'taine)
- PWA en JavaScript sans compilation (modules ES), hébergée sur GitHub Pages ; routes dans le hash (`#/`, `#/p/:id`, `#/p/:id/edit`, `#/p/new`, `#/more`).
- `js/app.js` : écrans en chaînes HTML, état global `S`, délégation d'événements (`data-action`).
- Deux stockages à interface identique : `js/store-demo.js` (navigateur, prix simulés) et `js/store-supabase.js`. `?demo` dans l'URL force le mode démo.
- Calculs purs et testés : `js/invest.js`. Courbes SVG : `js/chart.js`.
- Base : `supabase/schema.sql` (RLS, `is_owner()` sur la table `owners`). Les prix et les fiches de sets ne sont écrits que par la fonction `supabase/functions/bricklink` (clé service).
- Fonction `bricklink` : `lookup` (fiche du set) et `refresh` (relevé des prix). Signature OAuth 1.0 dans `bricklink.js`, partagé avec les tests Node. Déployée sans vérification JWT ; l'accès est contrôlé dans la fonction (compte `owners`, ou en-tête `x-cron-secret` comparé au secret du Vault par `public.brickfolio_cron_ok`, réservée à service_role). Déploiement depuis l'éditeur Supabase : coller `supabase/bricklink-editeur.ts` (généré par `node tests/build-function.mjs`).
- Relevé planifié : `supabase/cron.sql` (pg_cron + pg_net, lundi 5 h UTC, secret dans Vault `brickfolio_cron_secret`).
- Projet Supabase partagé avec Cap'taine (`zzhzdiuoonhvxndmziju`, plan gratuit limité à 2 projets) : ne pas réutiliser les noms owners, purchases, sets, prices, manual_values, runs, is_owner, touch, brickfolio_cron_ok, ni le bucket Storage `brickfolio-factures` (politique `brickfolio_factures_rw`).

## Décisions prises
- Source de prix : BrickLink, guide des prix « vendus » sur 6 mois (moyenne pondérée par quantité, Europe, EUR, TVA comprise), repli sur les annonces en cours. Un relevé par set, état et jour (`unique (set_no, condition, fetched_on)`).
- Valeurs manuelles (`manual_values`, par compte) fusionnées dans les relevés côté client (`manualRow`, `manual: true`) ; le même jour, la valeur manuelle prime sur BrickLink.
- Tableau de bord (v0.5) : `analyze()` → ligne (situation, tendances passées `trends()` 3 mois / 1 an, durée de détention) ; `stats()` sur les lignes filtrées ; `filterRows()` / `sortRows()`. Tendance : relevé de départ au plus près de la date de début (pas plus vieux que la moitié de la période), historique ≥ 60 % de la période. Pas de projection dans le futur (retirée à la demande de Cédric : pas fiable sur le marché LEGO). Filtres gardés dans `localStorage` `brickfolio-filters`.
- Nom affiché d'un achat (v0.5.1) : `purchases.name` (choisi, rempli par la facture sans « LEGO ») sinon catalogue BrickLink sinon numéro. Liste : date d'achat + boutique sous le numéro.
- Valeur d'un set sans prix = son coût. Rendement annualisé affiché seulement après 182 jours.
- Prix de vente saisi en net (total des boîtes vendues), frais d'achat inclus dans le coût. Vente partielle (v0.5.2) : `splitSale()` partage l'achat (vendu = nouvel id, frais au prorata arrondis au centime) ; la facture est partagée (`linkInvoice`) et le fichier n'est supprimé que si plus aucun achat n'y renvoie (`dropFileIfUnused`).
- Fenêtres (`<dialog>`) : réagir à l'événement `submit` du formulaire (`e.submitter.value`), pas seulement à `close` (pas déclenché dans certains navigateurs intégrés).
- Factures (v0.3) : un fichier par achat (PDF ou photo, 10 Mo max) dans le bucket privé `brickfolio-factures`, chemin `<uid>/<id achat>/<horodatage>-<nom>` ; colonnes `invoice_path/name/type` sur `purchases`. Ouverture par lien signé de 10 min. En démo : data URL dans `brickfolio-demo-factures` (3 Mo max).
- Lecture de facture (v0.4, gratuite, sans serveur) : `js/invoice-read.js` extrait le texte (pdf.js 4.10.38 pour les PDF, Tesseract.js 5.1.1 `fra+eng` pour les photos et PDF scannés, chargés à la demande depuis jsDelivr) ; `js/invoice-parse.js` en tire vendeur, date, sets, prix, frais, remise et total par règles (tests : `node tests/invoice.test.mjs`). Le choix d'une lecture par Claude (payante) a été écarté par Cédric. Frais affectés au premier set enregistré de la facture.
- Brickset (v0.6) : secret `BRICKSET_API_KEY`, `getSets` (POST, `userHash` vide), fiche fusionnée dans `sets` (`mergeSet` : BrickLink prime pour nom/image ; colonnes theme, subtheme, pieces, minifigs, rrp_eur = LEGO.com DE, launch_date, exit_date, brickset_url, brickset_at). Quota 100 appels/jour : fiche demandée une fois, puis tous les 30 jours, chaque semaine de 60 jours avant à 6 mois après la date de retrait (souvent repoussée par Brickset), plus du tout ensuite (`needsBrickset`) ; 25 max par relevé. Graphiques (v0.6.1) : repère « Prix LEGO » en pointillés orange (`retail` de `lineChart`) ; portefeuille = somme rrp × qté des boîtes détenues (`portfolioHistory(..., sets)`), affiché seulement si toutes en ont un. Marche sans clés BrickLink (lookup et refresh renvoient `bricklink: false`). Client : `setStatus()` (retired / retiring / available), `vsRetail()`, filtre « Chez LEGO », panneau « Fiche LEGO », colonnes CSV.
- Graphique du portefeuille (v0.7) : bascule « Plus-value » (par défaut) / « Valeur », gardée dans `S.f.chart`. Plus-value = latente (valeur − investi des boîtes détenues) + réalisée (ventes jusqu'à la date), `portfolioHistory` → `gain`, `realized` ; courbe à partir du premier prix connu (avant, la plus-value est inconnue, pas nulle) ; `lineChart({ signed: true })` : axe autour de zéro, valeurs signées ; pointillés = part réalisée.
- Style « Studio LEGO » (v0.8, choisi par Cédric parmi 3 pistes) : fond crème, carte jaune (`.hero`) réduite au résumé (plus-value totale, pastille %, latente · réalisée) ; courbe, bascules et chiffres dans la carte blanche `.hero-chart` (v0.8.2, « trop de jaune ») ; titres en police arrondie (`--round`) ; boîtes en vignettes photo 2 colonnes (`.positions.grid` / `.card`, fond pastel `tint(setNo)`, image en `mix-blend-mode: multiply`) ; bouton + rouge en relief. Fiche d'un set (v0.8.1) : vitrine photo `.showcase`, carte jaune `.detail-hero` (plus-value, courbe de la position, 4 chiffres), boutons principaux rouges en relief.
- Fin de relevé (v0.6.2–0.6.4) : `refreshSummary()` → une ligne ✓/✗ par source ; message « en cours » collant (`toast(..., { sticky: true })`) et roue `.spin` pendant `S.busy`.
- Opportunités (v0.10, onglet `#/opps`) : sets du **catalogue** (pas seulement détenus) dont le retrait approche. Fonction `scan` (cron quotidien `brickfolio-opportunites` 4 h 30 UTC) : balaie Brickset `getSets` par année (10 dernières années, ~20-25 appels, une fois par semaine), garde les vrais sets (catégorie Normal, ≥ 50 pièces) dont la date de retrait tombe dans 120 jours → table `bf_catalog` (fiche + demande Brickset `wanted_by`/`owned_by`/`rating`/`availability` + dernier relevé BrickLink neuf) ; puis relève les prix BrickLink des candidats par lots (budget de temps, jour après jour). `bf_watch` = sets surveillés (par compte). Préfixe `bf_` pour ne pas gêner Cap'taine. Note /100 dans `candidateScore()` (`js/invest.js`), grille v0.13 voulue par Cédric (méga sets, exclusivités, adultes) : taille du set 20 (max du prix LEGO et des pièces ; 400 € ou 4 000 pièces = max), exclusivité LEGO 15, gamme/licence 15 (`THEME_REPUTATION` ; UCS et modulaires au max), set pour adultes 10 (`age_min` Brickset ≥ 18 ; à défaut gammes adultes connues = 0,8), envie des collectionneurs 10, prime 10, tension 10, minifigs 5, durée de vente 3, délai 2 ; petits sets plafonnés (prix LEGO < 60 € → 45, < 100 € → 65, `SMALL_CAP`) ; critère inconnu compté pour moitié de ses points (« provisoire »). Faits du jour, pas de prédiction. Promos boutiques non prises en compte (Brickwatch : pas d'API ; Brickfact : piste future). « Je l'achète » ouvre le formulaire prérempli (`#/p/new?set=…&price=…`). Recherche (v0.14) : champ `data-opp-q` (numéro, nom, gamme ; sans accents, tous les mots) ; lien vert Brickwatch `https://www.brickwatch.net/fr-FR/set/<n°>/<NOM-EN-MAJUSCULES>.html` (`brickwatchUrl`).
- Avis de Claude (v0.12, gratuit : abonnement Claude de Cédric) : dans le détail d'une opportunité, « Demander à Claude ↗ » ouvre `https://claude.ai/new?q=…` avec la question préparée par `advicePrompt()` (fiche, marché, note de l'app, format imposé VERDICT / NOTE / PRIX MAX / RÉSUMÉ) et la copie aussi dans le presse-papiers ; « Coller la réponse » lit le texte avec `parseAdvice()` et l'enregistre dans `bf_advice` (insertion par les comptes owners ; dernier avis affiché, badge « Claude : … » sur la carte). L'appel direct à l'API (v0.11, payant) a été retiré à la demande de Cédric (trop cher).
- Images : BrickLink, repli sur Brickset (`images.brickset.com/sets/images/<no>.jpg`).
